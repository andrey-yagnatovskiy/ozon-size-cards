# Генератор карточек размеров для Ozon

Скилл для работы с этим репозиторием. Проект подставляет числовые размеры в готовые PNG-макеты карточек для маркетплейса. Товар, иконки, стрелки, логотип и фон не перерисовываются — меняются только цифры и единицы измерения.

## Когда применять

- Запустить веб-интерфейс или сгенерировать карточки из командной строки.
- Изменить размеры в прайсе и перегенерировать линейку.
- Добавить новую товарную линейку.
- Подобрать координаты блока с размером под новый макет.
- Разобраться, почему текст съехал, вылез за плашку или не совпадает с макетом.
- Обновить README или подготовить проект к публикации на GitHub.

## Структура проекта

```
app.py                          веб-интерфейс Flask, реестр линеек LINES
generate_cards.py               общие функции отрисовки, используются всеми линейками
generate_kaprolon_listy.py      капролон листовой      → толщина
generate_kaprolon_sterzhni.py   капролон стержневой    → диаметр + длина
generate_poliuretan_list.py     полиуретан листовой    → толщина
generate_poliuretan_sterzhen.py полиуретан стержневой  → диаметр + длина
layouts/                        PNG-макеты, 1254×1254
data/                           прайсы: TSV в кодировке cp1251, первая строка — заголовок
fonts/                          Montserrat-Black.ttf + OFL.txt
assets/                         логотип Rusbelt (png + svg)
templates/  static/             HTML и CSS интерфейса
output/<линейка>/               результат, в репозиторий не попадает
screenshots/                    скриншоты для README
```

Ключевая общая функция — `draw_value_with_unit` в `generate_cards.py`. Её используют все линейки.

## Запуск

Веб-интерфейс:

```powershell
python app.py
```

Открыть <http://127.0.0.1:5000>.

Пакетная генерация линейки:

```powershell
python generate_kaprolon_sterzhni.py
python generate_kaprolon_sterzhni.py --only-first
python generate_kaprolon_sterzhni.py --data "data/kaprolon-rods-sizes.txt" --output-dir "output/test"
```

Флаг `--only-first` генерирует одну карточку — всегда используй его для проверки перед полным прогоном.

## Правила

- Не перерисовывать товар, стрелки, иконки, логотип и фон. Меняются только числа и единицы измерения.
- Не менять разрешение макета.
- Не придумывать размеры и не заполнять пропуски в прайсе автоматически.
- Не перезаписывать содержимое `output/` без подтверждения пользователя: эти файлы уже могли быть загружены на Ozon.
- Перед изменением существующих карточек делать резервную копию папки линейки.
- После правки путей или координат сверять результат с прежним побайтово, если внешний вид меняться не должен.

## Как изменить размеры линейки

1. Открыть нужный файл в `data/`. Формат: TSV, кодировка **cp1251**, первая строка — заголовок, разделитель — табуляция.
2. Отредактировать значения. Единицы измерения в ячейках допустимы — скрипт оставляет только цифры.
3. Перегенерировать линейку и проверить изменившиеся карточки.

Кодировку и переносы строк CRLF при правке нужно сохранять, иначе скрипт не прочитает файл.

## Как добавить новую товарную линейку

1. Положить макет в `layouts/`, прайс — в `data/`.
2. Скопировать ближайший по смыслу скрипт `generate_*.py`.
3. Заменить константы `TEMPLATE`, `DATA_FILE`, `OUTPUT_DIR` и подобрать координаты блоков.
4. Зарегистрировать линейку в списке `LINES` в `app.py`: ключ, название, материал, подставляемые размеры, заголовки колонок, модуль, фабрику (`sheets_line` или `rods_line`) и шаблон имени файла.
5. Проверить: `python app.py`, открыть главную, убедиться, что линейка появилась и число размеров совпадает с прайсом.

## Как подобрать координаты блока на новом макете

Координаты подбираются измерением пикселей, а не на глаз:

1. Найти границы существующего текста на макете — колонки и строки тёмных пикселей в области плашки.
2. `*_DIGIT_LEFT` — левый край цифр, `*_BASE_Y` подбирается так, чтобы нижний край цифр совпал с оригиналом.
3. `*_DIGIT_H` и `*_UNIT_H` — высота цифр и единицы измерения в пикселях.
4. `*_CLEAR` — прямоугольник заливки: перекрывает старый текст с запасом, но не задевает границы плашки.
5. `*_BG` — цвет фона плашки, снимается пипеткой с макета. У разных макетов он разный, вплоть до оттенка 251/252/253.
6. `*_SPACING` — отступ между числом и единицей измерения.

Контрольная проверка: отрисовать поверх макета то же значение, что было в оригинале, и сравнить с исходником. Совпадение почти пиксель-в-пиксель означает, что координаты подобраны верно.

Важно: `draw_value_with_unit` рисует текст по `textbbox`, а не по типографской базовой линии. Реальный низ цифр оказывается ниже `base_y` примерно на величину верхнего отступа глифа. Проверяй положение замером готового изображения.

## Диагностика частых ошибок

| Симптом | Причина | Что делать |
|---|---|---|
| `FileNotFoundError` на макет или прайс | скрипт запущен не из корня проекта или файл переименован | пути строятся от `BASE_DIR`, проверить имя файла в константах |
| `UnicodeDecodeError` при чтении прайса | файл пересохранён в UTF-8 | вернуть cp1251 либо поправить `encoding` в `load_*` |
| Текст вылезает за край плашки | значение шире оригинального, Montserrat Black плотнее исходного шрифта | уменьшить `*_DIGIT_H` или не перерисовывать значение по умолчанию |
| Число съехало по вертикали | `*_BASE_Y` задан без учёта отступа `textbbox` | замерить низ цифр на готовом файле и сдвинуть константу |
| Видна полоса от заливки | `*_BG` не совпадает с фоном плашки | снять цвет пипеткой с макета |
| Интерфейс показывает старую вёрстку | Jinja кэширует шаблоны при `debug=False` | перезапустить `app.py` |
| Пустой список размеров | в прайсе меньше колонок, чем ожидает `load_*` | проверить, что разделитель — табуляция |

## Подготовка к публикации

1. Проверить, что `output/`, `Montserrat/`, `Montserrat.zip`, `__pycache__/` и `.claude/settings.local.json` перечислены в `.gitignore`.
2. Прогнать все линейки и убедиться, что генерация проходит без ошибок.
3. Проверить маршруты интерфейса: главная, страница линейки, генерация, превью, скачивание ZIP.
4. Обновить скриншоты, если интерфейс менялся.
5. Сверить `requirements.txt` с фактически используемыми библиотеками.
6. Коммит и push выполнять только после явного подтверждения пользователя.

## Контрольная проверка после генерации

- Количество файлов в `output/<линейка>/` равно количеству строк в прайсе.
- Имена файлов соответствуют шаблону линейки.
- На выборочных карточках — первой, средней и последней — числа совпадают с прайсом.
- Текст не обрезан, не вылезает за плашку и не накладывается на элементы макета.
- Разрешение осталось 1254×1254.
